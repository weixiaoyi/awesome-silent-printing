# 网页批量 / 面单打印

## 问题

仓配与电商工位经常要打**几十上百张**面单，不能靠人一张张点打印框。一张一弹框不是流程设计，是事故。

## 你需要什么

1. 能静默打到**指定名称**打印机的路径
2. 任务队列 / 批量 API（规模一大，纯前端 for 循环不够）
3. 稳定的模板渲染（HTML 或 ZPL）
4. 中途失败时的重试与日志
5. 打印机比提交慢时的背压

## 常见模式

| 模式 | 说明 | 更适合 |
|---|---|---|
| 浏览器 → 本机 Agent 批量 API | 工位延迟最低 | 操作员就在 SPA 里干活 |
| 服务端推送 → 工位 Agent 拉取 | 适合多打包台 | 不必一直开着浏览器 |
| 厂商 raw（ZPL） | 纯标签机很强 | 机队已标准化 ZPL |

## 推荐批量流程

```text
勾选订单
  → 渲染或拉取 N 份模板
  → 按批提交（或 20–50 一组分块）
  → 展示每笔状态（排队 / 打印中 / 完成 / 失败）
  → 只重试失败 id
```

### 分块

把 500 单丢进一次 `Promise.all` 往往更糟。建议：

- HTML 渲染类 Agent：每块 20–50 单
- 很小的 ZPL 字符串可以更大块
- 等一块完成（或并发限制 2–3）再下一块

## 失败分类

| 失败 | 操作员动作 | 系统动作 |
|---|---|---|
| Agent 离线 | 安装 / 启动 | 暂停队列；横幅提示 |
| 打印机离线 / 缺纸 | 处理硬件 | 标记可重试 |
| 模板 / 条码坏了 | 改数据 | 单笔失败，其它继续 |
| LNA / HTTPS | IT 修源站 | 见 [Chrome LNA](chrome-local-network-access.zh-CN.md) |
