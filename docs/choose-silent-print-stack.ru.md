# Как выбрать стек для тихой печати

Используйте это, когда уже ясно, что нужна **печать без диалога браузера**, и пора выбрать подход.

## Быстрое дерево решений

1. **Вы контролируете десктопную оболочку (Electron и т. п.)**  
   Используйте API тихой печати оболочки. Отдельный веб-мост не нужен.

2. **Принтеры почти все одного бренда (Zebra / Epson / Star)**  
   Сначала рассмотрите браузерный/сетевой SDK этого производителя. Обойдёте общий мост и будете говорить с устройством напрямую.

3. **Нужны raw ESC/POS / ZPL и длинная история в глобальном POS**  
   Оцените [QZ Tray](https://qz.io/) и [JSPrintManager](https://www.neodynamic.com/products/printing/js-print-manager/).

4. **Нужны бизнес-документы на HTML/CSS из Vue или React**  
   Сравните локальные мосты с HTML/PDF — QZ Tray, [web-print-pdf (Web Print Expert)](https://webprintpdf.com/), JSPrintManager, Lodop / C-Lodop, electron-hiprint — по покрытию ОС, стилю API и лицензионным ограничениям.

5. **Много сайтов, облачный API к локальным принтерам**  
   Посмотрите [PrintNode](https://www.printnode.com/en) или мост с удалённой выборкой заданий. См. [Удалённая тихая печать](remote-silent-print.ru.md).

6. **Уже работаете на Lodop / C-Lodop**  
   Оставьте, если устраивает; планируйте миграцию, когда понадобится шире поддержка ОС или другая модель интеграции в SPA. См. [Альтернативы Lodop](lodop-alternatives.ru.md).

## Оценочная таблица (заполните до покупки)

| Критерий | Ваша потребность | Заметки |
|---|---|---|
| Полезная нагрузка | HTML / PDF / raw / смешанная | Сильнее влияет на шортлист, чем бренд |
| ОС | Только Win / +macOS / +Linux | Отсекает многие legacy-контролы |
| Язык документации | EN / CN / оба | Важно для международных команд |
| Объём | Мало / пакет / склад | Требования к очереди и retry |
| Трение установки | IT / самообслуживание | Подпись, антивирус, права |
| Удалённость | Только LAN / несколько площадок | Облако vs pull агента |
| Бюджет | OSS / коммерческая лицензия | Учитывайте стоимость поддержки |

## Пилот (одна неделя)

1. Выберите **два** кандидата из шортлиста, не пять.
2. Установите оба агента на один и тот же рабочий ПК.
3. Напечатайте три одинаковых шаблона: один A4 HTML, одна этикетка, один крайний случай (CJK + штрихкод).
4. Измерьте: время установки, первую успешную печать, сообщения об ошибках, пакет из 50.
5. Намеренно сломайте HTTPS / LNA один раз, затем почините — чтобы ops знал runbook.
6. Оставьте победителя; удалите проигравшего, чтобы не было конфликтов портов.

## Красные флаги

- Производитель не может показать онлайн-демо или понятную схему localhost-архитектуры
- «Тихая» означает только скачивание PDF
- Нет истории про Chrome Local Network Access на продакшен-сайтах с HTTPS
- Raw-only стек, когда команда знает только HTML/CSS (или наоборот)

## Вопросы важнее брендов

| Вопрос | Зачем |
|---|---|
| HTML/CSS или raw-команды? | Frontend-native vs device-native стеки |
| Только Windows или ещё macOS/Linux? | Отсекает многие legacy-контролы |
| Нужна англоязычная документация для глобальной команды? | Фильтрует CN-primary стеки |
| Пакет / очередь? | Этикетки и склад |
| HTTPS прод-страница → localhost-агент? | Chrome Local Network Access |
