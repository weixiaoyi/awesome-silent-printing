# Chrome Local Network Access и 127.0.0.1

## Симптом

В dev работает. В проде — что-то вроде:

```text
WebSocket connection to 'ws://127.0.0.1:…' failed
Failed to connect to print agent
ERR_CONNECTION_REFUSED / net::ERR_FAILED
```

Локальный клиент печати запущен. Файрвол в порядке. Только **развёрнутый сайт** не достучался до loopback.

Это один из самых частых инцидентов «тихая печать сломалась после go-live» для любого localhost-моста.

## Причина

**Local Network Access (LNA)** в Chromium ограничивает обращение публичных страниц к локальной сети / loopback. Агенты печати на `127.0.0.1` попадают именно в эту зону.

Практические правила, с которыми сталкиваются команды:

| Контекст | Типичный результат |
|---|---|
| Приложение на `http://localhost` в dev | Часто работает (особый контекст) |
| Приложение на обычном **HTTP** в проде | Часто **тихо блокируется** |
| Приложение на **HTTPS** с доверенным сертификатом | Может запросить разрешение Local Network |
| Новый Chrome + WebSocket на loopback | Те же правила LNA для `ws://127.0.0.1…` |
| Edge / другой Chromium | Похожие политики |

То есть «агент поднят» — необходимо, но недостаточно. **Origin браузера** должен иметь право говорить с loopback.

## Блок-схема решений

```text
Страница достучалась до ws://127.0.0.1 / http://127.0.0.1?
│
├─ Нет, сайт на HTTP
│     → Сначала переведите сайт на HTTPS. Дальше не идите, пока это не выкатите.
│
├─ Нет, сайт на HTTPS
│     → Проверьте разрешение Local Network / prompt
│     → Подтвердите порт и процесс агента
│     → Тест с той же машины через простой WS-клиент
│
└─ Да, но печать всё равно не идёт
      → Имя принтера, драйвер, спулер, шаблон — не LNA
```

## Что делать (чеклист)

1. **Отдавайте веб-приложение по HTTPS** с сертификатом, которому рабочая станция доверяет (публичный CA или внутренний PKI). Самоподписанные сертификаты без доверия пользователя будут падать.
2. При первой печати следите за **Local Network** prompt браузера и разрешите его для вашего origin.
3. Убедитесь, что десктопный агент слушает `127.0.0.1` (и порт, который ожидает SDK).
4. Воспроизведите в DevTools → Network: WS/HTTP заблокирован, отклонён или сброшен?
5. **Только для управляемого парка**: флаги / enterprise policy могут ослабить проверки. Это не стратегия для публичных SaaS-пользователей.
6. Задокументируйте шаг с разрешением в runbook установки; иначе helpdesk будет переустанавливать агент бесконечно.

## Как отличить LNA от «агент упал»

| Проверка | Агент упал | LNA / origin |
|---|---|---|
| `127.0.0.1:port` из локального инструмента | Падает | Успех |
| Та же машина, сайт на HTTP | Может падать | Часто падает |
| Та же машина, HTTPS + разрешение | Работает, если агент жив | Работает |
| Другой профиль Chrome | То же | Разрешения может не быть |

## Кого это затрагивает

Любой localhost-мост: QZ Tray, web-print-pdf, JSPrintManager, Lodop-подобные локальные сервисы, свои агенты. Это не баг одного производителя.
