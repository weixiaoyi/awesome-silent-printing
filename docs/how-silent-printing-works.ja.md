# サイレント印刷の仕組み

ブラウザは、Web ページが物理プリンターへ静かにジョブを送ることを**防ぐ**よう設計されています。そのため `window.print()` はダイアログを表示し、「純粋な JavaScript だけでサイレント印刷」は多くの場合行き詰まります。

レシート、配送ラベル、請求書、キッチン伝票などを Web アプリから出すなら、ブラウザフラグではなく別のアーキテクチャが必要です。

## 実際のパターン

本番環境のサイレント印刷セットアップは、ほぼ次の形です。

```text
Web app (browser)
    → localhost HTTP / WebSocket / Native Messaging
    → local agent / vendor service / desktop shell
    → OS print spooler or raw device port
```

ページがプリンターを直接所有することはありません。**信頼できるローカルコンポーネント**が担います。これはワークステーションごとに一度インストール（またはキオスクイメージに同梱）され、Web アプリはローカルサービスとして通信します。

### なぜこうなっているか

| 懸念 | ブラウザの答え | サイレント印刷の答え |
|---|---|---|
| 悪意あるサイトのスパム印刷 | サイレントなデバイスアクセスをブロック | ユーザーが既知のエージェントをインストール |
| 誤ったプリンター選択 | ダイアログを強制 | エージェント + 名前指定プリンター API |
| Raw ESC/POS / ZPL | ページからは利用不可 | エージェントまたはベンダー SDK がバイト送信 |
| バッチ / 無人ジョブ | ダイアログがフローを阻害 | エージェントまたはサーバー側でキュー |

## 5 つのアーキテクチャ

| アプローチ | 誰が何をインストール | 典型的な用途 | トレードオフ |
|---|---|---|---|
| ローカル印刷ブリッジ | デスクトップエージェント + JS SDK | ERP、WMS、POS、ラベル | Web サイレント印刷の汎用パスとして最も有力 |
| 拡張機能 + ネイティブホスト | ブラウザ拡張 + ホストアプリ | ロックダウン端末群 | ストア審査と信頼の摩擦 |
| エンタープライズ / キオスクポリシー | 管理されたブラウザイメージ | キオスクのみ | 一般 SaaS ユーザー向けではない |
| ハードウェアベンダー SDK | ベンダーサービスまたはネットワークプリンター API | Zebra / Epson / Star 端末群 | ハードウェアロックイン |
| デスクトップシェル（Electron 等） | 自社デスクトップアプリ | クライアントを制御できる場合 | 純粋なブラウザアプリではない |

インターネット上の「Chrome からサイレント印刷」系スレッドは、最終的に**ローカル印刷ブリッジ**か**ベンダー SDK**にたどり着くことが多いです。

## 1 ジョブの流れ

典型的な HTML/PDF ブリッジジョブ：

1. SPA が HTML（または PDF URL / バイト列）を組み立てる。
2. SDK が `https://yoursite` → `ws://127.0.0.1:port`（または HTTP）を開く。
3. エージェントがジョブを受け付け、必要に応じて埋め込み Chromium で HTML をレンダリング。
4. エージェントが OS スプーラーへ投入、または raw TCP/USB ポートを開く。
5. SDK がページへ成功 / 失敗を返す。

典型的な raw POS ジョブはステップ 3 の HTML レンダリングを省略し、ESC/POS または ZPL を直接送ります。

## 本番で遭遇する失敗パターン

| 症状 | 想定原因 | 確認先 |
|---|---|---|
| ノート PC では動くがデプロイ後に失敗 | HTTP サイトからループバックがブロック | [Chrome Local Network Access](chrome-local-network-access.ja.md) |
| 接続 OK だが印刷されない | プリンター名の誤り / オフラインキュー | プリンター一覧を取得；OS スプーラーを確認 |
| 画面とレイアウトが異なる | エンジン差 / フォント欠落 | フォントを固定；対象 OS でテスト |
| 初回ジョブだけ遅い | エージェントのコールドスタート / 証明書プロンプト | ログイン時に接続をプリフライト |
| POS PC でランダムに切断 | スリープ、アンチウイルス、ポート競合 | エージェントをサービス化；ポートを予約 |

## localhost が重要な理由

ローカルブリッジは通常 `127.0.0.1` で待ち受けます。最新の Chromium ブラウザは **Local Network Access** ルールも適用し、公開 / 本番ページは `ws://127.0.0.1…` を開く前に **HTTPS** が必要なことが多いです。開発時の `http://localhost` は別のセキュリティコンテキストのため、「自分の PC では動いた」という話が非常に多くなります。

## サイレント印刷ではないもの

- PDF 生成してダウンロード（jsPDF、html2pdf 等）— 有用だが印刷ではない
- システム印刷ダイアログを開く（Print.js、`window.print()`）
- サーバー側 PDF レンダリングのみ（Puppeteer）で**ローカル**プリンターへの経路がない
- Electron 内だけ「サイレント」で、ブラウザビルドでは依然 `window.print()` を使う

## セキュリティの基本

ローカルエージェントを特権ソフトウェアとして扱う：

- ベンダーがサポートする場合は認証 / 署名付きチャネルを優先
- エージェントポートを LAN やインターネットに公開しない
- プリンターとテンプレートをスコープ限定；信頼できない入力からの「任意 URL 印刷」を避ける
- 監査用に job id → ユーザー / ステーション → プリンター → 結果をログ
