# Как работает тихая печать

Браузеры специально **не дают** веб-странице незаметно отправлять задания на физический принтер. Поэтому `window.print()` показывает диалог, а «тихая печать на чистом JavaScript» обычно тупик.

Если вы печатаете чеки, этикетки, счета или кухонные тикеты из веб-приложения, нужна другая архитектура — не флаг браузера.

## Реальный паттерн

Почти каждая рабочая схема тихой печати выглядит так:

```text
Веб-приложение (браузер)
    → localhost HTTP / WebSocket / Native Messaging
    → локальный агент / сервис производителя / десктопная оболочка
    → спулер ОС или raw-порт устройства
```

Страница никогда не владеет принтером. Это делает **доверенный локальный компонент**. Его устанавливают один раз на рабочую станцию (или включают в образ киоска), а веб-приложение общается с ним как с локальным сервисом.

### Зачем так устроено

| Задача | Ответ браузера | Ответ тихой печати |
|---|---|---|
| Злоумышленные сайты спамят печатью | Блокировать тихий доступ к устройству | Пользователь устанавливает известный агент |
| Выбор не того принтера | Принудительный диалог | Агент + API с именем принтера |
| Raw ESC/POS / ZPL | Недоступно со страницы | Агент или SDK отправляет байты |
| Пакетные / автономные задания | Диалог ломает поток | Очередь на агенте или сервере |

## Пять архитектур

| Подход | Кто что устанавливает | Типичное применение | Компромисс |
|---|---|---|---|
| Локальный мост печати | Десктопный агент + JS SDK | ERP, WMS, POS, этикетки | Лучший общий путь для веба |
| Расширение + native host | Расширение браузера + host-приложение | Управляемый парк | Модерация магазина + доверие |
| Корпоративная / киоск-политика | Управляемый образ браузера | Только киоски | Не для публичного SaaS |
| SDK производителя оборудования | Сервис производителя или сетевой API принтера | Парки Zebra / Epson / Star | Привязка к железу |
| Десктопная оболочка (Electron…) | Своё десктопное приложение | Когда клиент под вашим контролем | Не чистое браузерное приложение |

Большинство тредов «тихая печать из Chrome» в итоге сводятся к **локальному мосту** или **SDK производителя**.

## Что происходит при одном задании

Типичное задание HTML/PDF через мост:

1. SPA собирает HTML (или URL / байты PDF).
2. SDK открывает `https://yoursite` → `ws://127.0.0.1:port` (или HTTP).
3. Агент принимает задание, при необходимости рендерит HTML во встроенном Chromium.
4. Агент отправляет в спулер ОС или открывает raw TCP/USB-порт.
5. SDK возвращает успех / ошибку на страницу.

Типичное raw-задание POS пропускает HTML-рендер на шаге 3 и отправляет ESC/POS или ZPL напрямую.

## Сбои, с которыми столкнётесь в проде

| Симптом | Вероятная причина | Куда смотреть |
|---|---|---|
| На ноутбуке работает, после деплоя — нет | HTTP-сайт блокируется от loopback | [Chrome Local Network Access](chrome-local-network-access.ru.md) |
| Подключение OK, ничего не печатает | Неверное имя принтера / офлайн-очередь | Запросить принтеры; проверить спулер ОС |
| Вёрстка не как на экране | Другой движок / нет шрифтов | Закрепить шрифты; тест на целевой ОС |
| Первое задание медленное, дальше норм | Холодный старт агента / запрос сертификата | Preflight-подключение при входе |
| Случайные обрывы на POS-ПК | Сон, антивирус, конфликт портов | Агент как сервис; зарезервировать порт |

## Почему важен localhost

Локальные мосты обычно слушают `127.0.0.1`. Современный Chromium также применяет правила **Local Network Access**: публичной/продакшен-странице часто нужен **HTTPS**, прежде чем открыть `ws://127.0.0.1…`. Dev на `http://localhost` — другой контекст безопасности, отсюда и «у меня работало».

## Чем тихая печать не является

- Генерация PDF для скачивания (jsPDF, html2pdf…) — полезно, но это не печать
- Открытие системного диалога печати (Print.js, `window.print()`)
- Серверный рендер PDF (Puppeteer) без пути к **локальному** принтеру
- «Тихая» только внутри Electron, а в браузерной сборке всё ещё `window.print()`

## Базовая безопасность

Относитесь к локальному агенту как к привилегированному ПО:

- Предпочитайте аутентифицированные / подписанные каналы, где производитель их поддерживает
- Не открывайте порт агента в LAN или интернет
- Ограничивайте принтеры и шаблоны; избегайте «печатать любой URL» из недоверенного ввода
- Логируйте job id → пользователь/станция → принтер → результат для аудита
