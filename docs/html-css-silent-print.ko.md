# HTML/CSS 사일런트 프린트

## 팀이 원하는 이유

대부분의 비즈니스 UI는 이미 HTML/CSS입니다. 사일런트 프린트가 같은 템플릿을 재사용할 수 있다면 프론트엔드 속도가 유지되고, 모든 청구서마다 두 번째 ZPL/ESC/POS 스킬셋을 유지할 필요가 없습니다.

## 두 가지 레이아웃 모델

| 모델 | 장점 | 단점 |
|---|---|---|
| 로컬 Chromium/에이전트 경유 HTML/CSS | 웹 팀에게 친숙; 좋은 충실도 | 로컬 에이전트 필요 |
| Raw ESC/POS / ZPL | 정밀한 장치 제어 | 다른 스킬셋; 하드웨어 특화 |

많은 제품이 둘 다 혼합: A4 문서는 HTML, 열전사 티켓은 raw.

## 여기서 "print CSS"의 의미

브라우저 `@media print`만으로는 **사일런트 경로가 아닙니다** — 여전히 `window.print()`를 거칩니다. 로컬 에이전트와 함께 일반적으로:

1. 자체 포함 HTML 문자열(또는 URL)을 만듭니다.
2. 에이전트에 필요한 CSS 포함(인라인, 절대 URL 링크, 또는 번들).
3. SDK 옵션에 용지 크기 / 여백 / 프린터 이름 전달.
4. 에이전트 엔진(종종 Chromium)이 페이지 나누기 및 스풀링.

### 템플릿 체크리스트

- [ ] 명시적 페이지 크기 (A4, 100×150 mm, 80 mm 롤, …)
- [ ] 실제 용지와 맞는 여백
- [ ] 워크스테이션에 설치되거나 임베드된 폰트
- [ ] SVG 또는 고해상도 이미지로 바코드/QR (스캔 테스트)
- [ ] 마지막 행에서 잘리지 않는 테이블
- [ ] 뷰포트 전용 레이아웃 의존 없음 (`100vh` 함정)

## 실용 팁

- **인쇄 전용** 스타일시트 설계; 전체 앱 크롬 CSS를 맹목적으로 재사용하지 마세요.
- 라벨에는 `mm` / `in` 단위 선호; `px`만으로는 DPI마다 어긋납니다.
- Windows **와** Linux 작업대 모두 지원하면 중국어 / CJK 폰트 테스트.
- 템플릿 마이그레이션 시 배치 활성화 전 한 건 미리보기.
- 이미지는 작게 유지; 거대 PNG는 배치 처리량을 죽입니다.
- 정확한 열전사 커터 / 캐시 드로어는 raw 가능 브리지에서 raw 명령이 여전히 필요할 수 있습니다.

## 잘 맞는 경우

청구서, 명세서, 포장 목록, A4 보고서, HTML로 렌더링되는 많은 라벨 레이아웃.

## 잘 맞지 않는 경우 (raw / 벤더 SDK 고려)

- ESC/POS만 기대하는 초고속 주방 프린터
- 프린터 펌웨어에 ZPL 템플릿이 표준화된 Zebra 플릿
- 벤더 raw 외에 사용 가능한 Windows/macOS/Linux 드라이버 경로가 없는 장치
