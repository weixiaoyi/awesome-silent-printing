# Удалённая / серверная тихая печать

## Когда локального вызова из браузера недостаточно

- Упаковочные станции не должны открывать бизнес-SPA
- Задания создаются в центральном WMS/OMS
- Несколько столов должны потреблять одну очередь
- Ночная смена печатает задания, созданные на UI другой площадки

## Типичная архитектура

```text
Бизнес-сервер
    → очередь / webhook / websocket feed
    → агент печати на столе
    → локальный принтер
```

Браузер может использоваться только для настройки (привязка станция ↔ принтеры). Агент непрерывно pull-ит или получает задания.

### Два стиля транспорта

| Стиль | Как работает | На что смотреть |
|---|---|---|
| Cloud relay (PrintNode-подобный) | Server API → облако производителя → локальный клиент | Безопасность аккаунта, mapping по площадкам |
| Self-hosted pull | Агент опрашивает ваш API с токеном станции | Auth, backoff, durable queue |
| Transit / relay для designer-стеков | Дополнительный hop для hiprint-подобных клиентов | Операционная сложность |

## Заметки по дизайну

- **Аутентифицируйте агент**; не открывайте raw print port в интернет
- По возможности payload совпадает с локальной формой SDK (тот же HTML/PDF/raw)
- Офлайн-станции — durable queue и dead-letter для poison jobs
- Лог `job id → станция → принтер → результат` для ops
- Версионируйте шаблоны; плохой deploy должен откатываться без двойной перепечати истории
- Rate-limit на станцию, чтобы один стол не голодал остальных

## Чеклист безопасности

- [ ] Учётные данные станции можно ротировать
- [ ] TLS к вашему API
- [ ] Агент слушает только localhost для браузерных фич; удалённый канал — исходящий
- [ ] Нет «печатать произвольный URL» из недоверенных полей задания
- [ ] Аудит, кто может ставить в очередь на какую станцию

## Минимальный ops runbook

1. Станция offline → страница on-call с временем последнего heartbeat
2. Нет бумаги → показ на UI станции / LED, если есть
3. Poison-шаблон → карантин задания; алерт владельцам шаблона
4. Replay → только для явно failed id
