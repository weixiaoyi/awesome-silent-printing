# 远程 / 服务端推送静默打印

## 什么时候本机页面直连不够

- 打包台不必打开业务 SPA
- 任务在中心 WMS/OMS 生成
- 多工位消费同一队列
- 夜班要打其他站点界面创建的任务

## 常见架构

```text
业务服务端
    → 队列 / webhook / websocket
    → 工位打印客户端
    → 本地打印机
```

浏览器可能只用于配置（绑定工位 ↔ 打印机）；客户端持续拉任务或收推送。

### 两种传输风格

| 风格 | 怎么工作 | 注意 |
|---|---|---|
| 云中继（类 PrintNode） | 服务端 API → 厂商云 → 本机 Client | 账号安全、网点映射 |
| 自建拉取 | Agent 用工位 token 轮询你们 API | 鉴权、退避、持久队列 |
| 设计器栈的中继 | hiprint 类再多一跳 | 运维复杂度 |

## 设计注意

- **给客户端鉴权**；不要把裸打印端口暴露到公网
- 任务载荷尽量与本地 SDK 形态一致（同一套 HTML/PDF/raw）
- 工位离线要用可持久队列；毒丸任务进死信
- 记录 `任务 id → 工位 → 打印机 → 结果`
- 模板要有版本；坏发布能回滚，且不会把历史单打两遍
- 按工位限流，避免一台饿死其它台

## 安全清单

- [ ] 工位凭证可轮换
- [ ] 访问你们 API 走 TLS
- [ ] Agent 的浏览器能力只绑 localhost；远程通道走出站连接
- [ ] 不信任字段里不要「打印任意 URL」
- [ ] 审计谁能往哪个工位入队

## 运维手册（最低限度）

1. 工位离线 → 告警并带上上次心跳时间
2. 缺纸 → 工位 UI / 指示灯提示（若有）
3. 毒丸模板 → 隔离任务；通知模板负责人
4. 重放 → 只针对明确失败的 id
