# ブラウザからのサーマルレシートサイレント印刷

**Web ページからのサーマルレシート印刷**は通常サイレント印刷が必要です。レジ係やキッチンステーションは、伝票ごとにダイアログをクリックできません。

## 有効な方法

1. **ローカル印刷ブリッジ** — シンプルな伝票は HTML/画像/PDF、完全なデバイス制御は ESC/POS raw
2. **ベンダー SDK**（Epson / Star 系ネットワークプリンター — ページがプリンターまたはベンダーサービスと通信）
3. **デスクトップシェル**のサイレント印刷（POS Electron アプリを配布する場合）

## 無効な方法

- 本番サイレント経路としての `window.print()`
- ローカルプリンターエージェントなしの純 PDF ダウンロードライブラリ
- すべての「80mm CSS ページ」が raw コマンドなしでカットとドロワーを開くと仮定

## アーキテクチャの選択

| ニーズ | 向く方向 |
|---|---|
| ロゴ + 可変 HTML レイアウト、低ボリューム | ローカルエージェント経由 HTML |
| 高ボリュームキッチン、カッター、ドロワー、ブザー | QZ / JSPM / ベンダー SDK 上の ESC/POS raw |
| LAN 上の Epson/Star のみ | ベンダー ePOS / webPRNT 系 SDK |
| すでに POS デスクトップアプリを配布 | Electron サイレント印刷 |

## テンプレートのヒント

- 固定幅レイアウトを優先（例：**58mm / 80mm**）
- バーコードは高コントラスト；実際に使うスキャナーでテスト
- 重い CSS グリッドを避ける；サーマルエンジンとドライバーは厳しい
- カッター / キャッシュドロワーコマンドは **raw 対応スタックのみ**でテスト
- ESC/POS で CJK / アクセント付き文字のコードページを正しくエンコード
- ドライバーまたはエージェント更新後にキャリブレーション伝票を印刷

## フロントカウンター vs キッチン

| | フロントカウンター | キッチン |
|---|---|---|
| レイテンシ許容 | 低 | 非常に低 |
| 典型的ペイロード | HTML または ESC/POS | 多くは ESC/POS |
| 失敗 UX | レジ係にリトライ表示 | 自動リトライ + 目立つアラート |
| 複数プリンター | レシート + ラベル | ステーション / 品目でルーティング |
