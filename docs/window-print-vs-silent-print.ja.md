# window.print とサイレント印刷

よくある質問：`window.print()` をダイアログなしで呼べるか？  
短い答え：**通常のブラウザ Web ページではできません。**

ブラウザは印刷を特権的なユーザー操作として扱います。印刷 UI は安全弁です。`window.print()` をラップするライブラリ（Print.js や react-to-print など）も、最終的にはその UI に到達します。

## 並べて比較

| | `window.print()` / Print.js | サイレント印刷ブリッジ |
|---|---|---|
| ダイアログ | あり | なし |
| JS からプリンター選択 | 限定的 / 不可 | 可（ローカルエージェント経由） |
| バッチジョブ | 不向き | キュー向けに設計 |
| 名前指定プリンター / トレイ / 用紙 | ユーザー操作 | エージェント API |
| 何かをインストール | 不要 | 通常必要 |
| セキュリティモデル | ブラウザ制御 | ローカル特権ソフトウェア |
| 管理外 SaaS クライアント | 可（ダイアログ付き） | エージェントインストールが必要 |

## スプリントを無駄にする神話

| 神話 | 現実 |
|---|---|
| 「SaaS ユーザー向け Chrome フラグがあるはず」 | フラグ / ポリシーは管理端末向け。一般訪問者向けではない |
| 「サーバー上の Puppeteer がサイレント印刷」 | PDF / 画像を作るだけ。ユーザーの USB / ネットワークプリンターは動かせない |
| 「PDF ダウンロードで十分」 | ユーザーが手動印刷。名前指定プリンター / バッチなし |
| 「Electron のサイレント API がブラウザビルドでも使える」 | その API は配布するデスクトップシェル内のみ |

## `window.print()` で足りる場合

- たまのユーザー主導印刷（確認を期待する明細など）
- 明示的確認が望ましい法務 / 医療フロー
- 低ボリューム、キオスク / 倉庫自動化なし
- ローカルインストールを配布したくない

## サイレント印刷が必要な場合

- 配送ラベル、レシート、キッチン伝票
- 無人または高頻度ジョブ
- ダイアログが UX を壊す SPA フロー（スキャン → 印刷 → 次へ）
- ソフトウェアで選択する複数プリンターデスク（ラベル vs A4 vs レシート）

## 移行パス

1. **棚卸し**：今日何を印刷しているか — HTML スクリーンショット、CSS `@media print`、PDF、raw。
2. 対象ブリッジがレンダリングできるなら **HTML/CSS テンプレートを維持**；ZPL/ESC/POS 化が必要なものだけ書き換え。
3. [サイレント印刷スタックの選び方](choose-silent-print-stack.ja.md) で**ローカルエージェント**（またはベンダー SDK / Electron）を選ぶ。
4. `window.print()` 呼び出しを SDK 呼び出し（localhost 経由の HTML/PDF/raw）に置き換え。
5. **エージェント未インストール UX** を追加：接続検出、インストールリンク表示、準備完了まで「印刷」ボタンを無効化。
6. サイトを **HTTPS** でデプロイし、クリーンなワークステーションで [`127.0.0.1` への Local Network Access](chrome-local-network-access.ja.md) を検証。
7. ログ付きで 1 デスクを 1 週間パイロットしてから展開。

### 最小限のコード形状変更

Before:

```js
window.print();
```

After（疑似コード — API はベンダーにより異なる）:

```js
await printAgent.printHtml(document.getElementById('label').outerHTML, {
  printer: selectedPrinter,
});
```

## 完了とみなす前の受入テスト

- [ ] 正常系でダイアログが一切出ない
- [ ] ユーザークリックなしで正しいプリンターが選ばれる
- [ ] 1 件の失敗がバッチ全体をフリーズさせない
- [ ] 新規ブラウザプロファイルで HTTPS + LNA 権限を一度通過できる
- [ ] エージェントオフライン時にハングではなく回復可能なエラー
