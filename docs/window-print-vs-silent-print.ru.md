# window.print и тихая печать

Частый вопрос: можно ли вызвать `window.print()` без диалога?  
Краткий ответ: **нет, в обычной веб-странице браузера.**

Браузеры считают печать привилегированным действием пользователя. Диалог печати — предохранитель. Библиотеки вокруг `window.print()` (например Print.js или react-to-print) всё равно заканчиваются этим UI.

## Сравнение

| | `window.print()` / Print.js | Мост тихой печати |
|---|---|---|
| Диалог | Да | Нет |
| Выбор принтера из JS | Ограничен / нет | Да (через локальный агент) |
| Пакетные задания | Слабо | Рассчитано на очереди |
| Именованный принтер / лоток / бумага | Решает пользователь | API агента |
| Нужна установка | Нет | Обычно да |
| Модель безопасности | Контроль браузера | Локальное привилегированное ПО |
| Неуправляемые SaaS-клиенты | Да (с диалогом) | Нужна установка агента |

## Мифы, на которые уходят спринты

| Миф | Реальность |
|---|---|
| «Должен быть флаг Chrome для SaaS-пользователей» | Флаги/политики — для управляемых устройств, не для публичных посетителей |
| «Puppeteer на сервере — это тихая печать» | Он делает PDF/картинки; не управляет USB/сетевым принтером пользователя |
| «Скачивание PDF — почти то же» | Пользователь всё равно печатает вручную; нет пакета / именованного принтера |
| «Silent API Electron работает в браузерной сборке» | Эти API есть только внутри вашей десктопной оболочки |

## Когда хватает `window.print()`

- Редкая печать по инициативе пользователя (выписки, где подтверждение уместно)
- Юридические / медицинские сценарии с явным подтверждением
- Низкий объём, без киоска / складской автоматизации
- Вы не готовы ставить локальную установку

## Когда нужна тихая печать

- Этикетки доставки, чеки, кухонные тикеты
- Автономные или частые задания
- SPA-потоки, где диалог ломает UX (скан → печать → дальше)
- Несколько принтеров на столе (этикетка / A4 / чек), выбираемых в ПО

## Путь миграции

1. **Инвентаризируйте**, что печатаете сейчас: HTML-скриншоты, CSS `@media print`, PDF или raw.
2. **Сохраните HTML/CSS-шаблоны**, когда целевой мост их рендерит; переписывайте только то, что должно стать ZPL/ESC/POS.
3. **Выберите локальный агент** (или SDK производителя / Electron) по [Как выбрать стек](choose-silent-print-stack.ru.md).
4. Замените вызовы `window.print()` на вызов SDK (HTML/PDF/raw через localhost).
5. Добавьте UX **«агент не установлен»**: определение подключения, ссылка на установку, блок кнопки «Печать» до готовности.
6. Разверните сайт на **HTTPS** и проверьте [Local Network Access к `127.0.0.1`](chrome-local-network-access.ru.md) на чистой рабочей станции.
7. Пилот на одном столе неделю с логированием, затем rollout.

### Минимальное изменение формы кода

Было:

```js
window.print();
```

Стало (псевдокод — API различаются у производителей):

```js
await printAgent.printHtml(document.getElementById('label').outerHTML, {
  printer: selectedPrinter,
});
```

## Приёмочные тесты перед «готово»

- [ ] Диалог не появляется на happy path
- [ ] Нужный принтер выбирается без кликов пользователя
- [ ] Одно плохое задание не замораживает весь пакет
- [ ] Свежий профиль браузера один раз проходит HTTPS + разрешение LNA
- [ ] Офлайн-агент показывает восстанавливаемую ошибку, а не зависание
